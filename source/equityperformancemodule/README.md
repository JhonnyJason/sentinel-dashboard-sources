# equityperformancemodule

UI for the equity performance of a backtest, laid out in two rows: summary | equity curve, controls | trades chart.
Blocks are 320px wide, the charts shrink first and wrap below 800px screen width. Each row stretches to its taller box; the uPlot canvas is absolutely positioned so it follows the chart box (min 250px) instead of driving it.
Lives in the "Performance" tab (the default) of `#backtesting-details-container` (`backtesting-details.pug`).

- `setResults(summary)`: called by `seasonalitybacktestingmodule.run` with the `SymbolBacktester` summary.
- Renders only while the chart area has a width (tab visible); re-simulates via `tradesimulationmodule.simulate(summary, controls)` - no new backtest.
- Both charts share the x axis (`baseOptions`): x = point index (0 = start, i = after trade i), labelled with the year of trade i's exit date. Rebuilt on every render; a ResizeObserver re-renders when the chart area gets a size (container shown later, window resize).
- Equity curve: uPlot area, dashed value grid.
- Trades chart: bars per trade in %, a losing regular bar light red tinted, a half-transparent white zero line drawn under the bars; a trade cut by the stop-loss (orange) or take-profit (green) is a narrow bar in front of its faded theoretical bar (a second `simulate` without both levels). Max drops red, max rises green as dots; a theoretical extreme the cut trade never reached is faded. Bar widths capped in px; no grid. `barSeries` / `dotSeries` / `drawZeroLine` are exported for `seasonalityblocksmodule`. The y range comes from the theoretical values, so it stays fixed while dragging.
- Level lines `#equity-stop-loss-line` (yellow) / `#equity-take-profit-line` (green): overlay divs next to the uPlot root (not series: no hover point, full plot width, survive the chart rebuild), positioned in uPlot's `draw` hook. Hidden when the level is off. Dragging (pointer capture) writes the input (kept 0.1% off zero) and re-simulates via `onControlsChanged`.
- Creating a missing level: a press into the plot above zero (take-profit off) / below zero (stop-loss off) sets that level and hands the pointer capture to its line, so the same gesture drags it on. The side with an existing level ignores presses. Mouse: on pointerdown, with a crosshair cursor (`.level-creatable`) only where a press would create. Touch: drag and page scroll are both vertical, so speed decides - a fast first move (> `swipeSpeed`) scrolls, a slow one or a hold of `holdMs` grabs (`touchmove` prevented), a tap only sets. The `touchmove` listener sits on the touched node, as the render detaches it.
- `setResults` renders on the next frame: on a reload the region is hidden and shown within one frame, so the ResizeObserver alone would miss it.
- Controls (`#equity-controls`, one delegated `input` listener): stop-loss %, take-profit %, fees % per round trip (empty = off; a stop-loss/take-profit of 0 is cleared to empty on `change`), mode fixed stake | reinvest. Not persisted; a change only re-simulates.
